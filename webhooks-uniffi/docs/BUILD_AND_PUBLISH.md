# Build and Publish Guide for Chipa Webhooks FFI

This document outlines how to compile the core Rust library and generate/package bindings for each supported target language (Python, Kotlin, Swift, and C).

Because `chipa-webhooks-ffi` uses UniFFI, the build process always follows this general pattern:
1. Build the Rust core as a dynamic library (`cdylib`) and/or static library (`staticlib`).
2. Run the `uniffi-bindgen` tool to generate the language-specific wrapper code (e.g., `.py`, `.kt`, `.swift`).
3. Package the generated wrapper code *together* with the compiled Rust binary into the ecosystem's native package format (Wheel, JAR/AAR, XCFramework).

---

## Prerequisites

- **Rust & Cargo**: Installed via [rustup](https://rustup.rs/).
- **Target Toolchains**: Depending on your targets, you may need additional cross-compilation targets (e.g., `rustup target add aarch64-apple-ios` for Swift, or Android NDK for Kotlin).

---

## 1. Python (Creating a `.whl` / Wheel)

Python bindings use `ctypes` internally. You need to distribute the generated Python file alongside the compiled dynamic library (`.so` on Linux, `.dylib` on macOS, `.dll` on Windows).

### Build & Generate
```bash
# 1. Build the release library
cargo build --release

# 2. Generate Python bindings
cargo run --bin uniffi-bindgen --features bindgen -- generate \
    --library target/release/libchipa_webhooks.so \
    --language python \
    --out-dir bindings/python
```
*(Note: Use `chipa_webhooks.dll` on Windows or `libchipa_webhooks.dylib` on macOS)*

### Packaging into a Wheel
Create a basic Python package structure:
```text
chipa_webhooks_python/
├── pyproject.toml
└── chipa_webhooks/
    ├── __init__.py
    ├── chipa_webhooks.py    <-- Generated by UniFFI
    └── libchipa_webhooks.so <-- Copied from target/release/
```
In your `__init__.py`, simply export the module: `from .chipa_webhooks import *`.

Run the build tool to create the wheel:
```bash
pip install build
python -m build --wheel
```
You can now publish the resulting `.whl` in the `dist/` folder to PyPI using `twine`.
*(For production, you should use GitHub Actions to build a matrix of wheels for Windows, Linux, and macOS, and bundle them all).*

## 2. Kotlin / JVM (Creating a JAR or AAR)

Kotlin bindings use JNA (Java Native Access).

### Build & Generate
```bash
cargo build --release

cargo run --bin uniffi-bindgen --features bindgen -- generate \
    --library target/release/libchipa_webhooks.so \
    --language kotlin \
    --out-dir bindings/kotlin
```

### Packaging (Desktop / Server)
To publish to Maven Central, you typically use Gradle.
1. Place the generated `chipa_webhooks.kt` into your Kotlin source directory (e.g., `src/main/kotlin/com/chipa/webhooks/`).
2. Place the compiled `libchipa_webhooks.so` (and `.dll` / `.dylib`) into your resources directory so it gets bundled into the JAR (e.g., `src/main/resources/`). UniFFI automatically attempts to extract and load the library from the classpath.
3. Use the `maven-publish` Gradle plugin to create and publish the `.jar`.

### Packaging (Android AAR)
1. Add Android targets to Rust: `rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`
2. Compile for each using `cargo-ndk`.
3. Place the resulting `.so` files into your Android project's `src/main/jniLibs/<abi>/` folders.
4. Build the Android Library using `./gradlew assembleRelease` to get an `.aar`.

## 3. Swift (Creating an XCFramework / SPM)

Swift requires a module map (bridging header), the generated `.swift` file, and a static or dynamic library. Typically, iOS/macOS developers expect an `XCFramework` distributed via Swift Package Manager (SPM).

### Build & Generate
```bash
# Generate Swift bindings and C Header
cargo run --bin uniffi-bindgen --features bindgen -- generate \
    --library target/release/libchipa_webhooks.dylib \
    --language swift \
    --out-dir bindings/swift
```
This generates `chipa_webhooks.swift`, `chipa_webhooksFFI.h`, and `chipa_webhooksFFI.modulemap`.

### Packaging (XCFramework)
1. Build the Rust core as a `staticlib` for iOS and macOS targets:
   ```bash
   cargo build --release --target aarch64-apple-ios
   cargo build --release --target aarch64-apple-darwin
   cargo build --release --target x86_64-apple-darwin
   # Lipo the macOS targets together
   lipo -create -output libchipa_webhooks_macos.a target/aarch64-apple-darwin/release/libchipa_webhooks.a target/x86_64-apple-darwin/release/libchipa_webhooks.a
   ```
2. Create the `XCFramework` using `xcodebuild`:
   ```bash
   xcodebuild -create-xcframework \
       -library libchipa_webhooks_macos.a -headers bindings/swift/ \
       -library target/aarch64-apple-ios/release/libchipa_webhooks.a -headers bindings/swift/ \
       -output ChipaWebhooksFFI.xcframework
   ```
3. **Publishing via SPM:** Host the `.xcframework` (or compress it into a `.zip` and host the URL) and create a `Package.swift` that references it alongside your generated `chipa_webhooks.swift`.

## 4. C / C++

The C API is maintained manually to ensure standard ABI compatibility without relying on UniFFI's C generation (which is currently experimental/unstable).

### Build
```bash
# This builds the target dynamic and static libraries
cargo build --release --features c
```

### Packaging
To publish for C/C++ developers, you just need to distribute an archive (e.g., `tar.gz` or `zip`) containing:
1. The manual header file located at `bindings/c/webhooks.h`.
2. The compiled dynamic libraries (`.so`, `.dll`, `.dylib`) and static libraries (`.a`, `.lib`) from the `target/release/` directory.

## Future Continuous Integration (GitHub Actions)

When you are ready to automate this, create a `.github/workflows/release.yml` file. A standard CI/CD pipeline for a UniFFI project should:

1. **Matrix Build**: Run a job matrix on `ubuntu-latest`, `macos-latest`, and `windows-latest`.
2. **Compile Core**: Run `cargo build --release --all-features`.
3. **Upload Artifacts**: Upload the resulting `.so`, `.dll`, `.dylib`, and `.a` files as pipeline artifacts.
4. **Generate Bindings**: Have one job that runs `uniffi-bindgen` to generate the `.py`, `.kt`, and `.swift` files.
5. **Package**:
   - **Python**: Download the 3 artifacts (Linux, Mac, Windows), bundle them into 3 different Python wheels, and push to PyPI.
   - **Swift**: Download the Mac/iOS artifacts, run `lipo` and `xcodebuild -create-xcframework`, zip the result, and attach it to a GitHub Release.
   - **Kotlin**: Bundle the artifacts into a `resources` folder, build the Gradle project, and push to Maven Central.
